# 燕云十六声 · 坐标库（重构版 + WebUI + RPA 采集）

把一份手工攒的、格式很乱的燕云十六声坐标库，整编成**一份规范化数据集 + 一个能用的网页工具 + 一条能自动采集的流水线**。

原始库在 `D:\blog\yysls_coordinate`（122 个文件，GBK/UTF-8 混用，`.ini` 后缀其实是扁平 CSV，78% 是重复行）。
**原目录没有被改动**，只作为只读来源；本项目的 `raw/` 是清洗后的副本。

---

## 一句话开始

```bash
python tools/00_import_raw.py     # 从原始库导入（自动去重、按内容择优保留）
python tools/etl.py               # 规范化 → data/ + exports/
python tools/verify.py            # 数据对账（11 项校验）
node   tools/test_core.mjs        # 前端逻辑测试（75 项）
python tools/test_rpa.py          # 采集链路测试（34 项）

cd web && npm install && npm run dev    # 起本地开发服务 → http://127.0.0.1:5199
cd web && npm run build                 # 产出可部署的静态站 → ../dist
```

Python 3.10+ / Node 20+ 即可，**核心管线零第三方依赖**（纯标准库）；WebUI 只有 React + Vite。

| 项目 | 数量 |
|---|---|
| 原始文件 | 122 → 导入 112（丢掉 9 个内容完全重复的 + 1 个空文件） |
| 原始坐标行 | **27,099** |
| 规范化点位 | **6,071**（聚合掉 21,028 行冗余，78%） |
| 被多份文件收录的点 | 4,986 |
| 同坐标挂多个名字（待实地确认） | 693 |

| 导出可导入文件 | 49 个（按材料 / 分类 / 区域） |

### 原始数据的 5 类损伤，以及怎么处理的

| # | 问题 | 规模 | 处置 |
|---|---|---|---|
| 1 | 编码混用 | GBK 87 / UTF-8 35，全无 BOM | 逐文件探测，优先 UTF-8，回落 GB18030 |
| 2 | `.ini` 后缀骗人 | 89 个文件，**没有任何 `[Section]`**，实为扁平 CSV | 按 CSV 容错解析，分隔符空格/逗号都认 |
| 3 | 重复行 | 21,028 行 | **不删**：按 `(x,y,z,名称)` 聚合，重复次数保留成 `repeat` 字段 |
| 4 | 两行粘成一行 | 3 处 | 自动拆开，记进 `issues.json` |
| 5 | 手滑前缀 | 1 处 `3-3862.65` | 剥掉前缀，记进 `issues.json` |
| 6 | 缺名称 | 1 条（只有 x,y,z） | 标 `name_missing`，导出时补「未备注地点」 |
| 7 | 占位名 | 412 条「示例」「未备注地点」 | 名称没信息 → 改按**来源文件名**判类（`清河宝箱坐标.ini` → 宝箱） |
| 8 | 文案混在数据里 | 5 份注意事项 | 抽成 `notes.json`，在 WebUI 的「说明」页展示 |

> **第 3 条是关键**：重复行不全是脏数据。`黑乌石锁，青石锁.ini` 里 570 行**同一个坐标**都叫「传送」、
> `刷怪（膏和锁）` 里 506 行同坐标「锁」+ 506 行「膏」——这是导出工具靠重复 N 次实现
> 「打完传送回来再打」的挂机循环。简单去重会把这个语义抹掉，所以聚合时保留 `repeat`。
> WebUI 的导出面板有「按重复次数展开」开关，需要时能原样还原。

## WebUI 功能

左侧筛选 268px · 中间主区 · 右侧面板 372px，深色/浅色双主题，移动端折叠为抽屉。

### 列表视图
- 多关键词搜索（空格分词，全部命中）
- 字段前缀：`cat:材料` `region:清河` `mat:龙骨` `place:慈心山院` `layer:地下` `flag:placeholder_name` `src:合集`
- 区域 / 分类 / 材料 / 地点 / 高度层 / 数据标记 / 来源文件 七组筛选（组内「或」，组间「且」）
- 点列表头排序（名称 / 区域 / 材料 / 重复次数 / 来源数 / 高度…）
- 每一行一个复制按钮，直接给你 `x,y,z,名称`；坐标列点一下就是复制
- 勾选框标记「已收集」，进度存浏览器本地

### 地图视图（Canvas）
- 用游戏世界坐标 (x, y) 直接画点阵，北朝上
- 滚轮以光标为中心缩放、拖拽平移、悬停提示、点击联动详情
- 四种着色：按分类 / 按区域 / 按高度（地下→高台渐变）/ 按重复次数
- 点图例可单类显示隐藏；坐标网格刻度自适应（1/2/5 × 10ⁿ 步长）
- 可挂一张游戏地图截图当底图（透明度/缩放/位移可调，仅本次会话有效）

### 右侧面板（6 个标签页）
| 页 | 内容 |
|---|---|
| 详情 | 坐标大字 + 5 种格式一键复制、分类/区域判定依据、数据标记逐条解释、原始出处（文件 + 行号） |
| **附近** | 贴入当前坐标 → 按距离列出最近的点（三维 / 只看水平两种模式），带半径与分类过滤 |
| 导出 | 范围（当前筛选 / 选中 / 已收集 / 全部）× 格式 × 是否按重复次数展开，带预览，支持下载 .ini |
| 进度 | 按分类/区域/地点/材料看收集进度，批量勾选，导出已收集坐标 |
| 说明 | 原始作者的 5 份注意事项原文 + 署名声明 |
| 数据 | 从 27,099 行到 6,071 点的全过程、解析问题明细、分类判定依据分布、来源文件清单 |

### 快捷键
- `/` 聚焦搜索框 · `Esc` 关闭抽屉

### 分享链接
所有筛选状态、视图、选中项都写进 URL hash，复制地址栏就能把一份筛选结果发给别人。
（注意：链接里的 `+` 和空格都当分隔符处理——这是踩过坑之后特意兼容的。）

## 数据字典

`data/points.json` 里每个点位的字段：

| 字段 | 说明 |
|---|---|
| `id` | `p00001` 递增编号，稳定不变 |
| `x` `y` `z` | 世界坐标，`z` 是高度（-762 ~ 221） |
| `name` | **原始名称，逐字保留** |
| `base` `index` `note` | 从名称拆出的主体 / 尾部序号 / 括号或破折号备注 |
| `category` | 一级分类（材料 / 宝箱 / 蹊跷 / 玩法收集 / 动物 / 战斗 / 交互 / 设施与NPC / 地点标记 / NPC / 未标注 / 其他） |
| `categorySource` | 分类是怎么判出来的：`dict` 关键词 / `pattern` 正则 / `path` 来源路径 / `person` 人名启发 / `placeholder` 占位名 / `fallback` |
| `material` `place` | 材料名、地名（能认出来才有值） |
| `region` | 大地图：清河 / 开封 / 江南 |
| `regionSource` | 区域判定依据：`name` / `place` / `path` / `coord` / `nearest` |
| `layer` | 高度分层：地表 / 地下 / 深层地下 / 高台 |
| `repeat` | **同一坐标在单份文件里重复出现的最大次数**（刷怪循环） |
| `totalRows` | 该点在全部原始文件里出现的总行数 |
| `sources[]` | 出处清单：文件路径 + 行号 + 在该文件里出现几次 |
| `flags[]` | 数据标记，见下 |

### 数据标记（flags）

| 标记 | 含义 |
|---|---|
| `duplicated` | 重复出现（可能是挂机循环，也可能是多文件重复收录） |
| `cross_file` | 被 2 份以上原始文件收录 |
| `placeholder_name` | 原始名称是「示例」「未备注地点」这类没信息量的占位符 |
| `name_missing` | 只有 x,y,z 没有名称（全库 1 条） |
| `co_located_with_other` | 同一坐标挂着不同名称——**原始作者提示过**「坐标软件没刷新会导出一堆一样的坐标」，这 693 条建议实地确认 |
| `glued_split` | 原始文件里两行粘成一行，已自动拆开（3 处） |
| `stray_prefix` | 坐标前多了「3-」这类手滑前缀，已剥掉 |
| `region_inferred` | 区域是按坐标位置推断的 |
| `region_nearest` | 落在清河/开封的重叠带里判不出来，借用了最近邻的区域 |
| `suspicious_range` | 坐标超出合理范围 |

## 自动采集（影刀 RPA）

详见 **[`rpa/README.md`](rpa/README.md)**，包含三种采集方案的指令级搭建步骤、影刀变量绑定规则、
以及踩过的坑（**特别是「执行Python代码」指令必须点亮右上角 Python 图标，否则代码根本不执行**）。

快速理解：

| 方案 | 怎么干 | 要不要人在 |
|---|---|---|
| A 剪贴板桥接（推荐） | 按坐标记录热键 → 坐标进剪贴板 → RPA/脚本落盘 | 需要人在游戏里走 |
| B 屏幕 OCR | 定时截屏 → OCR 识别 HUD 上的坐标 | 无人值守 |
| C 清单跑图 | 读 `rpa/tasks/*.csv` → 逐个传送 → 记录有无 | 半自动，用来校验存量数据 |

`rpa/collector.py` 是**不依赖影刀**也能跑的剪贴板采集器，已经实测通过：
轮询剪贴板 → 解析 → 去重 → 追加 `x,y,z,名称` → 写 `session.json`。
采集产物落在 `raw/rpa/<会话>/collected.ini`，跑一次 `python tools/etl.py` 就并进主数据。

```bash
# 盯着剪贴板，坐标一变就记一条（Ctrl+C 停止）
python rpa/collector.py --out raw/rpa/我的手采/collected.ini --interval 250

# 生成待办清单给 RPA 跑
python rpa/make_tasklist.py --farm 龙骨 --farm 佛泪参
```

## 测试与验收

三套测试，共 **120 项断言**，全部通过：

| 命令 | 项数 | 测什么 |
|---|---|---|
| `python tools/verify.py` | 11 | **第二套实现独立复算**行数、抽样逐字比对原始行、紧凑版一致性、数值体检 |
| `node tools/test_core.mjs` | 75 | 前端解包、筛选计数与 facets 自洽、搜索、排序、附近、导出、进度、包围盒 |
| `python tools/test_rpa.py` | 34 | 两套解析器一致性（含**有意差异**的显式声明）、影刀片段独立运行、端到端入库 |

数据侧的硬保证：
- **零丢失**：`Σ totalRows == 27,099`，每个原始行都能追到文件 + 行号
- **零静默丢弃**：含坐标的文件里，没有既解析不出又没记进 `issues.json` 的行
- **可复现**：`00_import_raw.py` → `etl.py` 幂等，跑几遍结果一致

前端已用无头浏览器实测渲染（列表 / 地图 / 搜索三种状态），并做过两轮视觉审查。

## 已知局限

1. **分类靠词典 + 规则**，`其他` 还剩 15 个点位（都是「（挑战）两个雕像转至面向石碑即可完成」这类任务步骤描述）。想改进就编辑 `tools/taxonomy.py` 重跑 `etl.py`。
2. **区域兜底靠最近邻**：697 个点位（11%）按坐标判不出清河/开封，借用了最近的已知点，都带 `region_nearest` 标记。
3. **底图对不上游戏地图**：游戏内地图是另一套投影，网页地图用的是世界坐标，直接贴图会有形变。当参考用可以，别当精确对齐。
4. **影刀流程要在 GUI 里搭**：流程文件是它自己的格式，没法凭空生成。所以 `rpa/` 给的是指令级搭建指南 + 可粘贴代码 + 可独立验证的脚本。
5. WebUI 数据 550 KB，首屏要下载完才出表格（本地毫秒级，挂公网建议开 gzip）。
